Access control

Agents, groups, and authorizations

LinkedDataHub access control is based on the W3C ACL ontology.

Access modes

There are four access modes (classes of operation) that map to HTTP methods:

Access modes and the HTTP methods they permit
Mode Permits HTTP method
Read Read the contents, including querying them. GET
Write Overwrite the contents, including deleting or modifying them. PUT, PATCH, DELETE
Append Add information without removing or replacing any. POST
Control Change the authorizations that apply to the resource. — (no corresponding HTTP method)

Agents

An agent is a person or a piece of software, identified by a WebID, that can be authorized to have certain modes of access to certain dataspaces.

Groups

A group is a named group of agents to which an authorization can be given. It is a subclass of the foaf:Group class.

There are several default groups:

  • Owners
  • Writers
  • Readers
info

By default, only members of the owners group have access to the administration dataspace: its built-in Full control authorization grants the Control mode (along with read and write) to that group. See Authorizations.

Note that an agent being a member of one of the above groups does not automatically provide it with an authorization. A valid authorization for the whole group has to be present.

Authorizations

An authorization explicitly grants access for an agent or a group of agents to access a specific end-user dataspace document or a class of its documents.

An agent has to be authorized using the Control mode to be able to log in to the administration dataspace. By default such an authorization is granted to the owners group.

The default authorizations for groups and their respective access modes:

Default access for each group
Group Read access Write/append access Full control
Owners Read Write Control
Append
Writers Read Write —
Append
Readers Read — —

An authorization is a plain RDF resource. Granting the writers group full access to the Northwind orders container:

@prefix acl:  <http://www.w3.org/ns/auth/acl#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .

<#this> a acl:Authorization ;
    rdfs:label "Order management" ;
    acl:agentGroup <https://admin.localhost:4443/acl/groups/writers/#this> ;
    acl:mode acl:Read, acl:Append, acl:Write ;
    acl:accessTo <https://localhost:4443/orders/> .
ldh admin create authorization \
  --label "Order management" \
  --agent-group "https://admin.localhost:4443/acl/groups/writers/#this" \
  --to "https://localhost:4443/orders/" \
  --read --append --write

An authorization can also target a whole class of documents with acl:accessToClass. Granting the readers group read access to every container:

@prefix acl:  <http://www.w3.org/ns/auth/acl#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix dh:   <https://w3id.org/atomgraph/linkeddatahub/document-hierarchy#> .

<#this> a acl:Authorization ;
    rdfs:label "Container read access" ;
    acl:agentGroup <https://admin.localhost:4443/acl/groups/readers/#this> ;
    acl:mode acl:Read ;
    acl:accessToClass dh:Container .

A public-access authorization allows access for non-authenticated agents — the Publish stage of the tutorial shows the one ldh admin make-public creates, granting acl:Read to the foaf:Agent class on every document class.

info

The owner's and secretary's authorizations are stored under stable URIs (acl/authorizations/owner-webid/ and acl/authorizations/secretary-webid/), so reloading the admin dataset does not create duplicates.

Access requests

If access is denied due to missing authorization, the agent can ask for it by issuing a request to the dataspace's owners. The request indicates the request URI and access mode in question. The owners can then accept the request by creating an authorization with the provided information (possibly extending the requested access to a group of agents or a class of resources), or simply ignore it.

A request is data too — asking for write access to a Northwind order:

@prefix lacl: <https://w3id.org/atomgraph/linkeddatahub/admin/acl#> .
@prefix acl:  <http://www.w3.org/ns/auth/acl#> .

<#this> a lacl:AuthorizationRequest ;
    lacl:requestAgent <https://localhost:4443/agents/jane/#this> ;
    lacl:requestMode acl:Write ;
    lacl:requestAccessTo <https://localhost:4443/orders/10248/> .

Management

Access control actions and their CLI commands
Action CLI command
Create group ldh admin create group
Create authorization ldh admin create authorization
Add agent to group ldh admin add agent
Make a document public ldh admin make-public

To request access to someone else's dataspace, see the Request access guide. To open your data to the public, follow the Publish stage of the tutorial.
